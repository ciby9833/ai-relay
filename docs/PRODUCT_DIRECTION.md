# Relay 产品方向与改造计划（2026-10-29）

## 一句话定位

Relay 替你**持续跟进重要的事**；需要你介入时，把**背景、依据和下一步**准备好，让你少记、少找、少判断。

它不是消息转发器，也不是待办清单生成器。判断它好不好，不看它找出了多少条，而看：
真的事有没有漏、状态对不对、打扰了几次、你为一件事要点几下、翻几个地方。

## 目标用户与核心场景

用户是印尼 J&T Cargo 的管理者和骨干（50 人左右在用），每天的工作散落在飞书私聊、群聊、邮件、审批、日程、飞书任务和业务系统里。
他们的真实负担是：

| 场景 | 现在的负担 | Relay 应该做的 |
|---|---|---|
| 别人在群里/私聊里让他做事、问他拿主意 | 要记住谁问过什么、回没回 | 识别真正的请求和承诺，跟到有结果 |
| 他让别人做事、等别人答复 | 要记住在等谁、什么时候该追 | 到时间没结果才提醒，有结果自动结束 |
| 审批、邀请 | 量大、同类多 | 合并展示、一键处理，各自状态独立 |
| 开会 | 会前临时翻聊天、文档、上次纪要 | 会前把为什么开、进展、未决问题、他要准备什么整理好；会后按纪要跟进行动项 |
| 文档、表格、多维表格里的活 | 要自己去查、去填 | 对话里委托，Relay 准备好让他确认 |
| 个人习惯（哪些事要立刻说、哪些晚点说） | 被打扰太多或漏掉 | 从他在卡片上的反馈里学，规则他确认后才生效 |

## 三层信息，各有标准

| 层 | 是什么 | 进入标准 | 用户看得到吗 |
|---|---|---|---|
| **背景** | 理解他的工作用的材料：聊天、邮件、文档、会议纪要、已经结束的交流 | 所有读得到的、属于他的 | 不主动出现；在事项详情、会前准备、对话里作为依据出现 |
| **跟踪事项** | 需要持续跟到有结果的事 | 至少满足一条：①明确的承诺（谁答应了做什么）；②尚未解决、值得跟进的请求（有明确的交付物/决定/答复，且对方在等）；③影响他后续工作的等待；④他明确要求盯着的 | 在“待处理 / 在等别人”里，有统一状态 |
| **现在通知** | 现在告诉他会改变他下一步行动的事 | 跟踪事项里：今天到期、上级/客户在等、阻塞了别人、事故；或者一个结果解除了他的阻塞，他现在可以继续了 | 打断（飞书卡片 + 网页待处理红点）；其余进汇总或简报 |

拿不准是不是跟踪事项的（例如私聊里一句“这个可以发给我吗？”，前后文还不清楚），先作为**候选**留在后台：
不出现在看板、不推送；同一段对话有新消息时带着它再判断，超过 2 天没有新证据就自动放弃。

**私聊**默认是背景。问句、@、关键词都不是建事项的理由；要满足上面四条之一才进入跟踪。闲聊、临时询问已经答完、信息告知、已经结束的交流，都只是背景。

## 推送：先问“现在说会不会改变他下一步”

1. 推送前复查：已回复、已完成、已失效（会已经开了、审批别人处理了）、刚提醒过——不推。
2. 能准备的先准备：起草回复、找到相关材料、准备好审批/回复邀请的按钮。
3. 每张要行动的卡片写清楚：发生了什么、为什么现在提醒、依据（可点开原文）、可以直接做的下一步。
4. 完成的结果默认进汇总/简报；解除了他阻塞的结果（他在等的东西到了、今天要用）可以即时说。
5. 相似的事合并展示，但各自保留状态和按钮，处理一件不会误关其他。
6. 卡片标题的数量和正文说的是同一批事。

## 反馈放在真实卡片上

每件推送出去的事项卡片上都有：

- **已处理**：提醒之后他处理了（说明提醒有用）。
- **不用跟了** → 选原因：提醒前就处理了 / 不归我 / 不值得提醒 / 这类以后少提醒 / 重复了。

另外自动记录：提醒后多久处理、是否点开原文、是否直接在卡片上完成操作、是否对方先有了结果。
不把“点了”当成有用、“没点”当成没用——没反应的单独统计，不计入准确率。

评估指标（管理员只看数字）：

- 提醒准确率 = 提醒后处理 ÷ （提醒后处理 + 提醒前已处理 + 不归我 + 不值得 + 重复）
- 迟到率 = 提醒前已处理 ÷ 有反馈的
- 每人每天打断次数、每件事从提醒到处理的时间、在卡片上直接完成的比例
- 漏掉的：用户在对话里说“你没提醒我 X”或手动补充的

新旧链路（现有事项 vs 承诺账本）用同一套指标对比，再决定要不要换底层架构。

## 界面：对话用来解释和委托，不再承载所有通知

桌面端（左侧导航 + 主区域）：

- **待处理**（默认首页）：需要他做的事，按“现在要处理 / 今天 / 在等别人”分组；点开右侧是详情：发生了什么、依据、准备好的下一步、“问 Relay”。
- **会议**：今天和接下来的会，每个会的会前准备（为什么开、最近进展、未决问题、要准备什么；找不到资料会直说），会后的行动项。
- **进展**：已经有结果的事、简报和汇总，按天看。
- **对话**：解释、追问、委托（写文档、查表格、改多维表格……）；从事项点“问 Relay”进来时自动带上这件事的上下文。
- 长期任务、设置照旧。

移动端：底部 4 个入口（待处理 / 会议 / 进展 / 对话），详情全屏，返回回到列表。

同一件事只有一个状态；在飞书卡片、网页待处理、对话里任何一处处理，其他地方同步变化，不重复提醒。

## 改造优先级

| # | 改造 | 之前用户看到 | 之后用户看到 | 怎么验证 |
|---|---|---|---|---|
| 1 | 卡片口径 | 标题“1 件事需要你知道”，正文“有 3 件事……两件已完成” | 标题和正文说同一批事；已完成的结果不混进打断卡片，进汇总 | 单测：打断时标题数=正文涉及数；结果只在汇总出现 |
| 2 | 卡片上的反馈 | “我已处理 / 少提醒这类”，分不清提醒有没有用 | “已处理 / 不用跟了→五种原因”，网页同样 | 反馈写入独立表；管理员看到准确率、迟到率 |
| 3 | 私聊三层 | 私聊里的问句都可能变成待办：14 天 552 件，354 件没结，180 件挂了 3 天以上 | 只有明确承诺/在等的请求/他要盯的进跟踪；拿不准的作候选，补充上下文再定 | 用真实脱敏样例回放；上线后看私聊事项数、“不归我/不值得”比例 |
| 4 | 推送前复查 | 已经回过、审批别人处理了还提醒 | 推送前查最新状态，已处理的直接结束 | 单测覆盖已回复、已审批、会已开始；看“提醒前已处理”比例下降 |
| 5 | 会议 | 会前准备只按会议名搜文档、按参会人找邮件（同一人发的无关邮件也算进来） | 只用真正关联的材料：议程、会议描述里链接的文档、同一系列上次会的纪要和行动项、标题明确指向这个会的邮件/群；找不到就说找不到；会后按纪要提取行动项 | 单测：同一参会人的无关邮件不进入；没有材料时写明“没找到” |
| 6 | 界面分层 | 所有通知都进“主线”对话，和聊天混在一起 | 待处理 / 会议 / 进展 / 对话分开；从事项进对话自动带上下文 | Playwright：桌面和移动端布局、无横向滚动、状态同步 |
| 7 | 评估 | 单独的“帮 Relay 变聪明”页 | 指标来自真实卡片反馈；那一页只留给管理员做新旧对比 | 管理员页能看到每人准确率、打扰次数 |

之后：个人偏好学习（反馈 → 候选规则 → 他确认）、文档/表格委托的完成验证、是否以承诺账本替换现有事项链路（按第 7 项的同口径数据决定）。
