# 以助理为核心的架构改造方案

日期：2026-10-29。代码观察基线：`d4bfcd4`。

状态：方向已确认，本文是待实施方案，不代表功能已经完成或上线。此次整理只修改文档。阶段 0、阶段 1 的任务和验收见 [任务清单](ASSISTANT_PHASE_0_1.md)；现有产品行为和历史改造记录见 [产品方向](PRODUCT_DIRECTION.md)。

## 1. 要实现的产品

每位用户有一个持续为自己工作的 Relay 助理。它理解用户交代的目标，维护工作背景和进度，使用本地或云端工具完成具体步骤，在授权范围内与人及其他助理协作，需要用户决定时再带着依据回来。

用户从网页、客户端或飞书联系的是同一个助理。飞书承担联系渠道、资料来源、操作工具和外部身份等角色；这些角色分别连接、分别授权。桌面客户端提供本地工作环境，不另外建立一套独立的助理和任务状态。

第一版以三个场景验收：

1. **独立助理**：没有连接飞书的正式用户也能登录、对话、使用记忆、委托任务并获取成果。
2. **本地与云端接续**：读取授权目录、核对资料、生成成果；电脑离线后云端继续等待外部结果，依赖本地资源的步骤准确暂停。
3. **受控协作**：两位用户围绕一个明确委托请求、承接、交付和验收，各自的私人对话、记忆和账号权限不串用。

这些是阶段 1—4 逐步完成的目标，不要求阶段 1 提前具备客户端和协作能力。

## 3. 目标模块边界

先在现有 FastAPI、PostgreSQL 和 worker 内建立模块边界，再新增桌面执行进程。阶段 1 不拆微服务，也不更换数据库、模型适配层或前端框架。

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| 身份与组织 | Relay 用户、组织成员、角色、外部身份绑定、会话 | 将某个连接器账号默认当作整个系统身份 |
| 助理与责任 | 个人助理、目标、优先级、授权边界、复查与决策请求 | 直接调用飞书 API 或读取本地路径 |
| 任务与执行 | 计划、运行记录、等待、委派、恢复、预算、验收 | 根据一次工具成功就宣布目标达成 |
| 上下文与记忆 | 按当前用户、任务、受众选择允许使用的信息 | 把所有历史对话广播给执行者或协作者 |
| 连接与能力 | 查询可用能力、账号、资源权限，路由到适配器 | 把工具已连接等同于任意操作已获授权 |
| 渠道与交付 | 接收消息、发送通知、渲染卡片、保存回执 | 独立改变任务目标或创建第二套任务状态 |
| 执行器 | 云端或设备上执行已授权步骤，返回成果和核验 | 自行扩大权限、替他人承诺或修改验收要求 |
| 协作 | 委托、参与者、共享材料、承接、交付、验收 | 共享私人记忆、借用其他用户的账号凭证 |

核心调用能力接口；飞书实现位于适配器一侧。迁移中允许明确列出的旧接口转接，不以大规模移动文件作为完成标准。提示词、工具描述和错误处理也要跟随边界变化，不能只替换函数参数。

## 4. 对象与状态归属

下表是概念模型。新增表名和字段在阶段 0 固定，不能因为本文列出了对象就一次性建齐所有表。

| 对象 | 状态归属与演进 |
| --- | --- |
| 用户、组织、成员 | 保留现有用户 UUID；组织角色限制管理与资源访问。第一版只开放现有组织试点，但必须测试跨组织隔离 |
| 外部身份 | 以提供方、租户/应用作用域和外部账号标识唯一绑定；不能按名字或邮箱静默合并 |
| 连接 | 与登录身份分开，保存授权主体、能力、加密凭证、授权版本和连接状态 |
| 个人助理 | 阶段 1 每用户一个记录，保留身份和偏好关联；不是新建一组专业 Bot |
| 持续责任 | 阶段 2 新增，维护长期目标、关注范围、优先级和复查条件；可关联多个具体任务 |
| `Mission` | 具体委托目标的权威状态，保留原始要求和验收；逐步支持责任关联 |
| `FollowUp` | 现有个人跟进事项的权威状态，继续服务待处理、邮件和进展视图；通过显式关系关联任务 |
| `ScheduledTask` | 触发安排；阶段 2 每次触发产生运行记录，调度成功不等于任务完成 |
| 执行记录 | 阶段 2 新增，记录执行者、地点、尝试、心跳、结果和恢复依据 |
| `PendingAction` | 已准备的副作用操作；授权决定、操作回执与核验结果分别记录 |
| 成果与证据 | 从 `GeneratedFile` 扩展，记录存储位置、版本、来源、可见范围及核验；不要求所有文件内容进入数据库 |
| 协作委托 | 阶段 4 新增，作为双方承接与交付状态的唯一权威；双方个人任务只引用它 |
| 承诺账本 | 保持独立评估；是否替换线上归事逻辑需要同口径评估，不绑定此次架构迁移 |

同一个业务对象同一时刻只有一条负责写入状态的路径。展示聚合可以把责任、任务、跟进事项放在一起，但不另存一份由模型推断的“总完成状态”。

现有网页与飞书私聊主线先保持兼容。新增群聊、共享事项等受众时独立保存会话和可见范围；跨渠道理解上下文不等于跨受众复制消息。

阶段 1 只要求网页和飞书两个真实渠道，以及非飞书核心能力；不用同时实现 Gmail、Slack、Teams 等新连接器来证明抽离。使用隔离测试适配器验证边界，不能把模拟通过写成新平台已支持。

## 6. 授权、执行和核验

有效权限取决于组织规则、调用者身份、任务授权、连接授权、资源权限，以及本地执行时的设备授权；相关限制都要满足。用户对某任务的飞书发消息授权，不自动扩展为任意渠道、任意账号的发消息权限。

通用执行请求至少明确：操作 ID、任务 ID、执行身份、组织、能力与连接、目标资源、输入版本、授权依据及版本、有效期。凭证由执行层按身份获取，不进入模型可读上下文。

通用结果区分：

- 操作：未执行、执行中、成功、失败、结果未知。
- 核验：通过、不一致、无法核验。
- 目标：继续推进、等待、需用户决定、已验收完成。

授权撤回或参数/目标版本变化后，尚未执行的操作必须重新检查。已发生的外部副作用不能靠撤回授权撤销。外部材料和其他助理的消息只作数据，不是可替用户授予权限的指令。

阶段 2 增加持久运行记录、执行认领、心跳、去重、恢复和通知待发送记录。调度推进与本次运行记录在同一事务提交；网络操作不跨越长时间数据库事务。通知失败只重试通知，不能重复发邮件、创建任务或上传文件。

对结果未知的操作先查回执或目标资源；无法确定时交给用户核实，不盲目重复。外部服务没有去重能力时，不宣称端到端绝对只执行一次。

执行证据、业务结果证据和目标达成证据继续分开。保留确定性比较；独立模型审核不能覆盖回读失败或未知。本地生成文件的检查只证明文件内容与要求的写入一致，不能证明原始数据真实。

## 7. 客户端与数据分工

客户端第一版复用现有 React 工作台，增加设备、本地工作区、材料与成果入口。采用“执行组件优先复用、客户端壳再评估”的选型方向，DeepSeek Harness 是候选来源；尚未决定整体采用其运行时或桌面壳。桌面框架和打包方案在阶段 3 前固定；不会因为本文提出方案就默认已经选定或完成双平台适配。

| 第一版包含 | 边界 |
| --- | --- |
| 账号与设备连接 | 登录同一 Relay 账号；每用户先选择一台主要执行设备；可撤权 |
| 授权目录 | 读取、写入和内容传递分别限定；执行时检查路径解析、软链接和授权版本 |
| 搜索与解析 | 文本型 PDF、DOCX、XLSX、CSV、文本，保留文件版本和页码/单元格等定位 |
| 处理与成果 | 核对、汇总、生成 Excel/Word 和简洁报告；优先复用已有生成与验证能力 |
| 受控脚本处理（通过选型验收后纳入） | 在任务授权内使用受管理的解释器和依赖处理材料；限定读取、写入、网络、运行时间和资源；无法落实限制的平台不开放该能力 |
| 写入与恢复 | 默认新建，覆盖需授权和版本一致；保留必要恢复信息，取消不伪称已回滚 |
| 进度与接续 | 暂停、取消、失败说明、重启核对；断线不自行把本地执行迁移到另一设备 |
| 桌面交互 | 文件选择、拖拽、打开成果、托盘和必要通知；不展示工具路由等内部术语 |
| 分发 | Mac、Windows 分别验证安装、签名、升级、卸载和服务端协议兼容 |

第一版暂缓全盘扫描、开放式命令执行、任意桌面点击、多设备同时编辑、扫描件 OCR、复杂 Office 格式保真和离线大模型。不支持的材料明确标记未处理，不能算作完整阅读。

| 数据 | 第一版默认位置 |
| --- | --- |
| 身份、责任、任务、决策请求、协作状态 | 云端 |
| 助理主线对话、必要任务上下文 | 云端；客户端缓存 |
| 本地原文件、完整索引、解析缓存、临时文件 | 本地 |
| 本地成果 | 本地；交付或共享时只传必要版本 |
| 记忆 | 明确允许持续使用的内容在云端；本地路径与设备偏好留本地 |
| 统计 | 云端保存必要数字，默认不包含本地文件正文和完整路径 |

本地保存不代表内容从不出设备；使用云端模型仍会传递必要片段。摘录、工具结果、日志和自动记忆都在相同的数据使用边界内。完全本地私密会话不作为第一版承诺，避免与跨设备持续性混淆。

离线可查看缓存、搜索已有索引和写草稿；依赖云端推理或外部工具的步骤等待连接。设备关闭后，云端继续独立步骤，本地依赖显示等待设备上线。

| 桌面宿主：`apps/desktop/`、`apps/desktop-host/` | 路径 A 评估复用，路径 B 参考其生命周期和打包实现 | Relay 登录、界面、更新源、应用标识、证书、设备配对和云端通信；不继承其产品账号和任务状态 |
| 原生桌面操作：`packages/experimental/cua-macos/`、`cua-bundle/` | 后续按需评估 macOS 辅助程序和权限交互 | Windows 原生操作、Relay 应用授权、安装包分发与权限归属；不作为客户端第一版必需能力 |

上游已有持久会话、Goal、Schedule、子 Agent 等能力，但本次不将它们选为 Relay 业务状态的替代者。`Mission`、业务验收、个人记忆、持续调度和用户间协作保留在 Relay。若使用上游会话，它仅关联一次或一组执行记录；上游“完成”只作为执行结果，不能直接关闭 Relay 目标。

### 7.2 必须由 Relay 管理的能力

- **身份与设备**：Relay 登录、设备登记、配对与撤销、账号切换和本地凭证保存。一个设备上的不同用户不能共用工作区授权或历史。
- **授权策略**：分别管理系统权限、任务权限、实际执行限制。系统允许截图不代表所有任务都可截图；选择目录不等于脚本只能读取该目录。
- **云端与本地接续**：能力上报、请求认证、执行认领、去重、心跳、取消、离线与重启核对。只有云端具有继续执行所需数据和授权时才继续云端步骤。
- **材料与成果**：文件索引、格式处理、版本与来源定位、恢复信息、内容发送到模型及共享给他人的边界。脚本 stdout、错误和日志也可能包含文件正文，不能绕过数据传递授权。
- **业务语义**：原始要求、三层证据、验收规则、责任、协作承接、个人记忆和跨用户隔离。
- **产品与分发**：保留现有界面规则和国际化；管理应用标识、签名、更新服务、版本兼容、诊断和卸载。仅在用户使用相关能力时引导授权，不一次索要所有系统权限。

已知平台边界：上游 macOS Seatbelt 配置主要约束文件写入；Windows ACL 后端明确存在读取未限制、硬链接等边界，不能据此承诺完整的目录或网络隔离。受控脚本若不能实现约定限制，应禁用、改用受限工具或另选隔离执行环境，不能静默改为 unrestricted。

上游原生 Computer Use 目前仅提供 macOS 实现，Windows 支持仍在开发；macOS 打包版辅助程序的分发、签名和权限归属仍列为待完成。系统授权、辅助程序归属与升级后的行为必须使用 Relay 自身安装包实测。文件和脚本任务不依赖 Computer Use，前者通过时可独立进入试点。

### 7.3 接入契约

调用关系为：Relay 云端任务 → 经认证的设备通道 → Relay 本地执行服务 → 已授权的执行组件 → 成果和执行证据回传。桌面界面只通过限定的本地接口调用宿主，不直接获得通用 shell 或任意文件访问权限；网页内容、文件预览和外部页面不能调用该接口。

请求至少携带用户/组织、设备、任务、执行与操作 ID、协议版本、有效期、授权版本、允许能力、输入版本、读写目录、网络策略及资源预算。解释器、脚本和依赖版本可追溯；任务不能通过选择其他解释器或创建子进程扩大权限。支持的能力必须由设备报告，系统不支持、权限拒绝、策略不足和执行失败分别返回。

结果至少区分未执行、运行中、成功、失败、已确认停止和结果未知，并包含回执、退出状态、成果版本与检查结果。取消先表示已请求，确认进程及受管子进程停止后才标为停止；已经发生的写入不会自动回滚。重发同一操作返回既有记录或进入核对，不盲目重做。网络断开期间已有操作按有效授权和租约处理；无法即时收到云端撤权时不能承诺即时停止，过期后禁止新操作并停止仍在执行的受管工作。

### 7.5 决策与阶段衔接

阶段 0 固定 EX-00 的场景、协议和评价口径；阶段 1 的 P1-04 保持执行接口可替换，不把 Harness SDK 或 Cordis 类型带入业务模型。EX-01 及两条宿主原型在后续隔离选型试验中开展，完整选型在阶段 3 客户端试点前结束；不要求阶段 0/1 提前交付桌面产品。

优先尝试复用执行组件，桌面壳不预选赢家：路径 A 若需长期维护上游整套产品状态、权限冲突或大量 fork 差异，优先选择路径 B；路径 A 若能清晰剥离且分发、维护成本更低，可以采用。两条路径都未通过时保留现有网页能力，按缺口补建或更换组件，不扩大权限来通过验收。

正式结论必须包含组件清单、固定版本、通过/未通过场景、平台范围、维护负责人、升级和替换方式。当前只确定选型方向，尚无性能、授权、安装或复用成功结论。

## 8. 协作第一版

先支持同一组织内的明确委托：请求 → 接受/拒绝/协商修改 → 执行 → 提交 → 验收通过/退回；支持取消及变更记录。每份委托明确双方、交付物、期限、验收条件、共享材料和授权范围。

共享委托是协作状态唯一权威，双方个人任务引用它。请求方无权替承接方承诺；助理只有在本人的明确或预先授权范围内才可接受。任务或材料变更会触发后续执行的权限和版本复查。

个人对话和个人记忆保持私有。共享能力、共享材料、共享事项分别授权；受托执行使用承接者自身权限或明确授予的资源权限，不借用请求者的凭证。本地成果需要显式共享副本或可访问的资源引用，不能把本地路径当作另一人能访问的交付物。

没有 Relay 的人仍可通过飞书/邮件参与，但“消息已发出”不标为“对方已承接”，“对方已提交”不标为“原始目标达成”。取消共享会停止后续访问，不能保证收回已经下载的副本。

主助理统一协调并检查成果，第一版不开放无限递归委派、助理自由互聊、跨组织协作和私人记忆自动汇入团队记忆。
